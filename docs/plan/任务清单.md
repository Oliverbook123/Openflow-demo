## 阶段 2：Rust 后端基础（~2 天） ✅ 已完成

- [x] **2.1 数据模型定义**
  - `FlowNode`：节点 ID、类型、提示词(prompt)、状态、依赖文档路径列表
  - `FlowEdge`：边 ID、源/目标节点、条件（预留）
  - `FlowProject`：项目元数据、节点列表、边列表
  - `NodeStatus` 枚举：`PendingEdit | PendingExec | Running | NeedsIntervention | Completed`
- [x] **2.2 文件存储层**
  - `FlowStorage`：读写 `.openflow/config.json`（节点配置）
  - 任务文档管理：`.openflow/tasks/` 目录的创建、读写、版本化
  - 实现 Tauri 命令：`flow_load_project`、`flow_save_project`
- [x] **2.3 状态机**
  - `FlowStateMachine`：维护节点状态流转逻辑
  - 依赖检测：前序节点是否 Completed
  - 状态切换校验（如：`PendingEdit → PendingExec` 需提示词已填写）
  - Tauri 事件通知：`node_status_changed`
- [x] **2.4 Claude Code 集成**
  - `ClaudeCodeRunner`：通过 `std::process::Command` 调用 `claude` CLI
  - 构造参数：`--prompt` + `--context`（依赖文档路径）
  - 流式读取 stdout/stderr，通过 Tauri 事件推送到前端
  - 超时控制、错误重试
- [x] **2.5 文件系统工具**
  - 读取工作区文件列表（为路径选择器提供数据）
  - 文件路径校验（依赖文档是否存在）
  - Tauri 命令：`list_workspace_files`、`validate_path`

## 阶段 4：前端-后端联调（~2 天） 🚧 进行中

- [ ] **4.1 状态同步**
  - 前端初始化时调用 `flow_load_project` 加载项目
  - 节点状态变更通过 `invoke` 调用后端命令
  - 后端通过 Tauri `emit` 推送状态变更到前端
  - 自定义 hook `useFlowState` 封装同步逻辑
- [ ] **4.2 执行流程**
  - 用户点击"执行节点" → 前端 `invoke("flow_execute_node", { nodeId })`
  - 后端检查依赖 → 更新状态为 Running → 启动 Claude Code 进程
  - 后端流式推送日志 → 前端实时显示执行输出
  - 完成后更新状态为 Completed 或 NeedsIntervention
- [ ] **4.3 文档交接可视化**
  - 执行中的节点显示"正在生成文档..."
  - 完成后显示产物文档路径，可点击打开
  - 依赖文档缺失时，高亮提示并提供跳转

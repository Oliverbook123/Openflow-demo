**OpenFlow v0.1 版本设计书**

**一、项目概述**

1. **项目名称**：OpenFlow
2. **项目目标**：
构建一个可视化AI编程任务编排工具，通过节点画布将Claude Code的代码生成能力整合为结构化任务流，实现多步骤任务的直观编排与执行管理。v0.1版本以**线性任务流**为核心，验证节点状态流转、文档交接机制及基础稳定性。
3. **核心价值**：
    - 填补Claude Code等工具在**多步骤任务管理**上的空白，提升复杂任务的结构化协作能力。
    - 通过显式文档交接（而非系统级数据流）降低技术复杂度，贴合用户实际开发习惯。
    - 提供可视化的任务依赖关系和状态监控，增强流程可控性。

**三、核心功能（v0.1）**

1. **节点管理**：
    - 支持创建、删除、拖拽节点，节点类型限定为“代码生成”（后续扩展其他类型）。
    - 节点配置：编辑初始提示词（需包含文档路径引用，如`参考文件：/path/to/doc.md`）。
2. **状态流转**：
    - 状态定义：待编辑、待执行、执行中、需介入（文档缺失/错误）、完成。
    - 手动触发：用户手动执行节点，依赖前序节点产物就绪。
3. **文档交接**：
    - 用户显式指定依赖文档路径，节点执行时通过`--context`参数传入Claude Code。
    - 产物存储：节点生成文档自动存入`.openflow/tasks`目录，版本号记录（如`node_A_v2.md`）。
4. **错误处理**：
    - 需介入状态细分：显示错误原因（如“文档不存在”、“解析失败”），提供跳转前序节点入口。
5. **界面交互**：
    - 画布支持缩放、节点连线显示依赖关系，状态高亮（如红色=需介入，绿色=完成）。

**四、技术选型与实现方案**

1. **前端框架**：Tauri 2 + React + React Flow
    - 轻量级跨平台，React Flow处理画布交互。
2. **后端语言**：Rust
    - 高性能处理API调用与文件操作，确保安全性。
3. **Claude Code集成**：
    - 通过官方API调用任务，不修改其底层逻辑，确保兼容性。
    - 命令示例：`claude-code start --prompt "实现功能" --context /path/to/doc.md`
4. **状态同步**：
    - 后端通过Tauri事件系统实时同步节点状态到前端（如`app.emit_all("node_status", {id, status})`）。

**五、开发计划（v0.1）**

1. **阶段划分**：
    - **阶段1（1-2周）**：基础架构搭建（Tauri + Rust环境、画布基础交互）。
    - **阶段2（2-3周）**：核心功能实现（节点创建/编辑、状态机、文档路径管理、Claude Code调用）。
    - **阶段3（1-2周）**：测试与优化（错误处理、界面流畅性、文档版本管理）。
2. **里程碑**：
    - 4周后：完成MVP，支持线性任务流手动执行与基础错误反馈。

**六、风险与对策**

1. **文档路径错误风险**：
    - 对策：节点编辑器强制要求填写依赖路径，并提供项目内文件路径智能提示。
2. **Claude Code API限制**：
    - 对策：限制并发调用，记录API响应日志，预留错误重试机制。
3. **状态一致性**：
    - 对策：节点状态变更通过后端统一处理，避免前端直接修改，确保同步。

**七、后续版本规划（v0.2+）**

- 支持分支任务流（条件节点、并行执行）。
- 自动解析提示词中的文档路径，减少手动输入。
- 集成Git实现任务流版本控制。
- 引入模板库，提供常见任务流模板（如“设计→编码→测试”）。

**八、总结**
OpenFlow v0.1以**线性任务流、显式文档交接、手动控制**为核心，验证可视化编排与Claude Code的协同可行性。通过聚焦基础功能与降低技术复杂度，快速构建MVP，为后续扩展奠定基础。
